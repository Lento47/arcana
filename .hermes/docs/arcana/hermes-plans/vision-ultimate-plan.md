# Arcana: The Ultimate Plan

## What Arcana Has After Phase A

Arcana will have:
- Typed claims: observed, assumed, derived, verified, contradicted
- Evidence linked to claims
- Completion contracts extracted from user intent
- Proof obligations for important assertions
- A hard completion gate
- A tamper-evident execution trace
- TUI commands to inspect claims, assumptions, obligations, contracts, and traces
- Benchmarks showing whether this actually reduces false completion

**Arcana at that point becomes:** A coding agent that knows the difference between saying something happened and proving that it happened.

---

## The Vision

Arcana becomes the trusted execution layer for autonomous software work.

Any model can reason underneath it (Claude, GPT/Codex, Gemini, Grok, local models, future models), but Arcana controls:
- What the model is allowed to do
- What evidence is required
- Whether a result is actually complete
- What remains uncertain
- How the execution can be inspected, reproduced, approved, or reversed

**Arcana should not compete by having "the best chatbot." It should become the operating system around models.**

Models provide intelligence. Tools provide capability. Arcana provides truth, control, and accountability.

---

## The Mission

Turn probabilistic AI proposals into reliable, verifiable, and governed outcomes.

In practical terms:
- Never confuse output with completion
- Never confuse confidence with correctness
- Never silently convert assumptions into facts
- Never let untrusted content grant itself authority
- Never perform consequential actions without traceability
- Make autonomous work cheaper without weakening verification

## Phases B–H: Evidence-Driven Evolution

### Phase B — RunProof
Turn the trace into a complete execution record:
- Artifact hashes
- Environment manifests
- Reproduction metadata
- Audit replay
- Live revalidation
- Proof levels
- Exportable reports

Arcana can then answer: What changed? Why did it change? What verified it? Can it be reproduced? What has become stale since then?

### Phase C — Capability Security
Prevent models and external content from controlling the system improperly:
- Explicit capabilities
- Tool-level authorization
- Workspace trust policies
- Prompt-injection boundaries
- Secret isolation
- Approval requirements
- Reversible and irreversible action classes

Arcana becomes safe enough for more than local code editing.

### Phase D — Provenance-Aware Learning
Upgrade the current memory system:
- Quarantine new learnings
- Attach sources and evidence
- Detect contradictions
- Scope facts to repository, branch, user, or environment
- Expire stale knowledge
- Revoke poisoned memories
- Sync knowledge without losing provenance

**Arcana does not merely remember — it knows why it believes something.**

### Phase E — Independent Verification
Add challengers and specialized verifiers:
- Proposer
- Challenger
- Test verifier
- Specification verifier
- Security verifier
- Final proof aggregator

Arcana begins actively trying to disprove its own work before presenting it as complete.

### Phase F — Efficiency Intelligence
Make reliability affordable:
- Model routing by task
- Context virtual memory
- Cache-aware prompt construction
- Tool-schema paging
- Cheap models for simple work
- Strong models only when uncertainty demands them
- Verification effort proportional to risk

**North-star metric:** Verified outcomes per unit of cost (not tokens consumed, not messages generated).

### Phase G — Governed Autonomy
Allow Arcana to run longer and complete larger objectives:
- Persistent work programs
- Dependency-aware task graphs
- Recovery after failures
- Approval checkpoints
- Budget enforcement
- Self-correction
- Continuous revalidation
- Human intervention only when judgment is genuinely required

This is where Arcana moves beyond a coding CLI into an autonomous engineering runtime.

### Phase H — Creativity and Realization
Add the originality layer:
- Non-generic concept generation
- Structural novelty checks
- Multiple independent design directions
- Anti-slop analysis
- Feasibility scoring
- Automatic prototype realization
- Testing whether a creative idea works, not merely whether it sounds original

**An idea is not valuable until Arcana can turn it into a defensible artifact.**

## Permanent Innovation Areas

1. **Epistemic Intelligence** — How Arcana knows what is factual, assumed, stale, conflicting, or requiring verification; when to abstain.
2. **Verified Execution** — Proving bugs were reproduced, patches fixed the cause, no regressions, deployment succeeded, requirement satisfied.
3. **Governed Autonomy** — Scoped authority, approvals, rollbacks, budgets, policies, sandboxes, recovery.
4. **Efficient Reasoning** — Better context selection, caching, model routing, stopping criteria, less repeated exploration, reuse of proven knowledge.
5. **Learning Without Corruption** — Evidence-based memory, contradiction handling, confidence decay, revalidation, versioning, revocation.
6. **Human–Agent Control** — Command spine, live claims and obligations, proof receipts, clear intervention points, inspectable delegation, immediate understanding of risk and completion.

## Long-Term Product

Arcana should eventually support three modes:

1. **Personal Engineer** — A powerful CLI for one developer: understand → plan → implement → verify → learn
2. **Team Execution System** — Shared governed workflows: delegate → review → approve → attest → reproduce
3. **Enterprise Autonomous Runtime** — Policy-controlled agents operating across repositories, CI/CD, infrastructure, security operations, incident response, internal tools, and research workflows, with every action linked to identity, permission, evidence, cost, and outcome.

## The Moat

The moat is not any individual feature. Claude, OpenAI, Google, xAI, and Vercel can reproduce features.

The moat is the accumulated system:
- Execution histories + verified outcomes + model reliability data
- Project knowledge with provenance + reusable proof obligations
- Organizational policies + trusted workflows + evaluation infrastructure

Over time, Arcana learns:
- Which model works for which task
- Which verification method catches which failure
- Which repositories have which risks
- Which claims commonly become false
- Which workflows reliably produce accepted outcomes
- How much verification is required for each risk level

**That compound data and architecture are harder to copy than a command or UI feature.**

# After Everything Is Complete — The Future

Assume everything is complete. Arcana stops being a product roadmap. It becomes a platform category.

## What Arcana Is Then

Arcana is the operating system for trustworthy autonomous work. Models are interchangeable compute providers. Just as Kubernetes governs containers without caring which application runs inside them, Arcana governs agents without depending on which model performs the reasoning.

The core product becomes:
- An autonomy runtime
- A policy engine
- A verification system
- An institutional memory
- An evidence ledger
- A human–agent operating interface

## Four Larger Stages

### 1. Arcana Becomes a Protocol
Open the foundations so external systems can produce and consume Arcana-compatible proofs:

- Arcana Claim Protocol
- Arcana RunProof Format
- Arcana Capability Manifest
- Arcana Completion Contract
- Arcana Evidence Schema

Arcana becomes a standard for answering: What did the agent do? Under whose authority? Based on what evidence? What was verified? What remains uncertain? Can the result be trusted?

### 2. Agent Marketplace & Execution Network
Once work can be objectively evaluated, Arcana allows specialized agents to compete for tasks:

Task contract → Multiple agents propose execution → Arcana evaluates cost, trust, evidence, and historical success → Best agent executes → Independent verification → Outcome and proof recorded

An agent's reputation could become: 87% verified success in Rust compiler errors, 94% regression-free rate, average cost $X, average completion time Y, calibration error Z.

This creates an evidence-backed economy of machine labor.

### 3. Organizational Infrastructure
Companies define how autonomous work is permitted:

> "No production deployment without: passing integration tests, security verifier approval, two independent evidence sources, human approval above the defined risk level, and a valid rollback plan."

Arcana enforces this across every model and agent. The organization's policies, proof history, accepted workflows, and verified knowledge become durable institutional infrastructure.

### 4. Autonomy Control Plane
Thousands of agents operating continuously under shared policy:

Organization objective → Arcana decomposes programs of work → Specialized agents execute concurrently → Evidence and dependencies flow through RunProof → Verifiers challenge outcomes → Humans intervene only at judgment boundaries → Arcana continuously revalidates

Users stop micromanaging prompts. They define objectives, constraints, budgets, risk tolerance, authority, and acceptance criteria. Arcana manages the execution.

## Research Problems That Never End

- **Autonomy quality** — How much larger and longer can a task become before human intervention is required?
- **Verification quality** — How to prove increasingly complex outcomes (formal methods, simulation, runtime monitoring, counterfactual testing, continuous verification, real-world outcome measurement).
- **Collective intelligence** — How hundreds of agents collaborate without duplicated work, groupthink, cascading errors, or coordination overhead.
- **Economic intelligence** — Is another $1 of inference likely to improve the outcome? Should this task use a stronger model? Should we verify again? Should we stop, escalate, or reformulate?
- **Continuous self-evolution** — Arcana proposes improvements to itself, but every improvement passes the same system: hypothesis → implementation → evaluation → adversarial verification → controlled deployment → rollback capability.

## The Business Future — Three Layers

1. **Arcana Community** — Open runtime and protocols: CLI/TUI, claim and evidence schemas, local RunProof, local models, basic policies, plugin and agent SDK. Drives adoption and prevents Arcana from becoming another closed wrapper.
2. **Arcana Cloud** — Managed infrastructure: proof synchronization, cross-device memory, hosted agents, remote execution, team collaboration, evaluation infrastructure, model routing, audit storage.
3. **Arcana Enterprise** — Organizational governance: identity and access, policy enforcement, compliance evidence, private model routing, signed attestations, organization-wide memory, deployment controls, security and audit integrations.

## The Ultimate Competitive Position

- Claude, Codex, Gemini, Grok → superior model products
- Vercel → superior at web deployment
- GitHub → superior at repository distribution

**Arcana sits above and between them:**
- Models generate. Platforms host. Tools execute.
- **Arcana governs the entire operation.**

A company could replace Claude with Gemini, replace one cloud provider with another, or change its IDE — and retain its Arcana contracts, policies, evidence, memory, workflows, and execution history. That makes Arcana the durable layer.

## The Real Future

The mission evolves from *"Make an agent reliable"* to *"Make autonomous organizations possible without surrendering control, truth, or accountability."*

**Final vision:** Every consequential machine action should be authorized, explainable, evidence-backed, reversible where possible, and accountable to human intent. Arcana becomes the infrastructure that makes that normal.

The CLI is where Arcana begins. The future is an operating system, protocol, marketplace, and governance layer for machine intelligence.

# Competitive Landscape

## Closest Competitors

### 1. Microsoft Agent 365 + Agent Governance Toolkit
Closest to Arcana's long-term control-plane vision. Agent 365 is a control plane for observing, securing, and governing agents across an organization. The open-source Agent Governance Toolkit adds deterministic runtime policies, agent identity, sandboxing, capability delegation, audit records, SRE controls, and framework-independent integrations.

**Limitation:** Action governance, not reasoning governance. Governs tool calls, permissions, resources, and agent communication — not whether a model's claims are supported or whether its declaration of completion is justified.

**Arcana opportunity:** Govern both reasoning and action.

### 2. IBM watsonx Orchestrate Agent Control Plane
Centralized layer to observe, govern, manage, and optimize enterprise agents, with watsonx.governance tracking lifecycle, evaluation, compliance, transparency, and accountability.

**Limitation:** Enterprise agent inventory, monitoring, compliance, operational management, performance evaluation. Does not publicly document Arcana-style typed claims, completion contracts, per-claim proof obligations, or a coding-agent completion state machine.

### 3. Arcade
Enterprise action runtime for agents: per-user authorization, secret management, runtime policies, agent registries, version control, centralized governance, and OpenTelemetry audit logs. Strongly overlaps with Arcana's future capability-security layer.

**Limitation:** Primarily answers "Is this agent authorized to perform this action?" Arcana additionally answers "Is the claim true, was the requested outcome achieved, and is the evidence sufficient to declare completion?"

### 4. ProofAgent
Evaluates agents, classifies risk, generates evidence reports, and gates releases with pass/review/block decisions. CI can fail based on the governance decision.

**Overlaps:** Evaluation, release gates, compliance evidence, adversarial testing, proof-like reports.

**Limitation:** Focused on evaluating and releasing agent systems, rather than governing every claim and obligation inside a live coding session. Closest competitor to Arcana's false-completion evaluation direction.

### 5. LangSmith
Records full agent trajectories, evaluates tool usage and decision paths, runs online and offline evaluations, can identify recurring failures, propose fixes, and generate regression evaluators.

**Limitation:** Tracing something does not mean proving it. Does not prevent an agent from declaring success because a task-specific proof obligation remains unresolved.

### 6. Temporal
Durable execution, recovery, persistent state, pause/resume behavior, and workflow replay after crashes. Proves that a workflow can continue reliably.

**Limitation:** "The process executed reliably." Arcana: "The required outcome was demonstrated with sufficient evidence." They could eventually be complementary rather than competitors.

### 7. OpenAI Agents SDK
Sessions, structured tracing, guardrails, handoffs, human approvals, and resumable approval flows. Strong construction primitives, but not currently presented as a full vendor-neutral epistemic governance runtime.

## What Appears Genuinely Uncommon

No established product publicly combines all of these in one live coding runtime:
- Observed versus assumed versus derived claims
- Evidence attached to individual claims
- User-intent completion contracts
- Automatic proof obligations
- A hard state-machine gate against false completion
- Tamper-evident session traces
- Provenance-aware learning and memory
- Capability-secure tool execution
- Model-independent coding-agent operation
- Persistent autonomous workflows
- TUI inspection of claims, uncertainty, evidence, and obligations

**That combination is Arcana's potential differentiation.**

## The Sharpest Position

Arcana is not entering an empty market. Microsoft in particular is already pursuing the broad "operating system/control plane for governed agents" thesis. Arcana should not position itself merely as "Governance for AI agents" — that is already crowded.

**The sharper position:** Arcana governs whether autonomous engineering work deserves to be considered complete.

Or: **The evidence and completion kernel for coding agents.**

- Microsoft governs what an agent may do
- LangSmith records what an agent did
- Temporal ensures the process keeps running
- ProofAgent evaluates whether an agent release passes policy
- **Arcana governs whether the actual engineering claim has been proven**

That is narrower — but significantly more distinctive.
