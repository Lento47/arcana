# Session Titles — Fix "Untitled" in Session Picker

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Sessions in the session picker show "Untitled · date" instead of meaningful titles derived from the first user message. Fix the engine to generate titles for all sessions (including subagent sessions).

**Architecture:** The engine's `prompt.ts` auto-title generation has a guard at line 206: `if (input.session.parentID) return` — this skips title generation for subagent sessions. Remove this guard. Additionally, titles may not be generated if the session is created without a first user message. Add a fallback: show the last non-empty user message text as the title in the TUI dialog.

**Tech Stack:** TypeScript, effect-ts, SolidJS.

---

## Full Code Path Audit

### How titles flow

```
Engine creates session: title = "New session - 2026-07-25T03:40:00.000Z" (default)
  ↓
User sends first message
  ↓
prompt.ts:206 — checks parentID → subagent sessions SKIPPED
prompt.ts:207 — checks isDefaultTitle → only if still default
prompt.ts:214-215 — extracts first user text → titleFromUserText
prompt.ts:222 — sessions.setTitle() → persists to database
  ↓
TUI session list:
  sync.data.session → session.title
  displaySessionTitle() → if default title, check firstUserText from messages
  if messages not loaded → "Untitled · date"
```

### The bug

**Line 206:** `if (input.session.parentID) return` — subagent sessions never get auto-generated titles. They stay as "New session - ..." forever. The TUI falls back to "Untitled · date".

**Line 207:** `if (!Session.isDefaultTitle(input.session.title)) return` — if the title was already set (manually or by a previous auto-generation attempt), skip. This is correct.

## Regression Analysis

**REG-1: Removing parentID guard generates titles for subagent sessions.**
Subagent session titles would be based on the subagent's first user message (which is the task description). This is actually BETTER — subagent sessions get meaningful titles like "Fix fs.rs: replace crate::crypto::KeyStore" instead of "Untitled". **No regression.**

**REG-2: `firstRealUserIndex` may return -1 for sessions without user messages.**
The function skips message indices 0-1 (system + greeting). If there are no user messages, `idx === -1` → returns early. Title stays default. **No change — existing behavior preserved.**

**REG-3: Concurrent rename race condition.**
Line 219-220 re-checks `isDefaultTitle` after fetching current session. Protects against the user manually renaming the session while auto-title is in progress. **No change — existing guard preserved.**

## Risks

2. **Existing sessions won't retroactively get titles.** Only NEW sessions (created after this fix) will auto-generate titles. Old sessions stay "Untitled". **Acceptable — they'll get titles on next message.**
