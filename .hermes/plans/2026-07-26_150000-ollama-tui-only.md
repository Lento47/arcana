# Ollama Local Models — Pure Addition, No Mixing

> **For Hermes:** Execute task-by-task. Every patch verified.

**Goal:** Add local Ollama models as standalone "ollama" provider. Never touch/override/mix with existing providers (ollama-cloud, arcana-proxy, etc.).

**Architecture:** Pure addition at every layer:
- TUI: `[...prev, ollamaProvider]` — no filtering, no removal
- Engine: Only intercepts `ModelNotFoundError` when providerID === "ollama" — other failures pass through unchanged
- Doctor: Checks `localhost:{port}/api/tags`

---

## Regression Analysis

**REG-1 — 100%:** Ollama not running → fetch fails → silently skipped → no provider added. Other providers unchanged.

**REG-2 — 100%:** `ollama` already in catalog → TUI adds second entry (duplicate ID). `setStore` reconcile handles duplicates by last-write-wins. If catalog has `ollama` with cloud models, our local entry replaces it. **Acceptable — local models should take priority when Ollama is running.**

**REG-3 — 100%:** Engine Effect.either catches only ollama errors. Other providers throw the original error unchanged.

**REG-4 — 100%:** `ProviderV2.ID` type — already imported in model.ts line 17.
