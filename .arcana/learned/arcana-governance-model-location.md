# arcana governance model location

Arcana security model is documented in Master Design §8–15 and §29; core invariant is ¬Authorized(q) ⇒ ¬Executed(q)

Arcana's governance follows "the model proposes, the engine decides, the proof records." Core invariant: `¬Authorized(q) ⇒ ¬Executed(q)` — every execution must trace to a fresh ALLOW decision with matching request hash, principal, and policy version. Intent binding is risk-scaled: LOW → active capability suffices; MODERATE → user request/task binding; HIGH → contract criterion; CRITICAL → explicit approval + active contract. Remote content can never create consequential intent. Full detail lives in the Master Design document (§8–15, §29).

**Why:** Quick reference prevents re-deriving the pipeline when answering governance questions or evaluating action authority.

**How to apply:** For questions about the security model, consult the Master Design sections directly rather than paraphrasing from memory; classify any proposed consequential action through the LOW/MODERATE/HIGH/CRITICAL intent-binding tiers.
