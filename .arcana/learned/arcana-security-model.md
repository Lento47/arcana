# arcana security model

Arcana governance: model proposes, engine decides, proof records — nothing executes without a fresh ALLOW

Core invariant: `¬Authorized(q) ⇒ ¬Executed(q)` — every execution traces to a fresh ALLOW with identical request hash, principal, and policy version.

Pipeline: intent binding (risk-scaled: LOW→active capability, MODERATE→user request/task binding, HIGH→contract criterion, CRITICAL→explicit approval + active contract; remote content never creates consequential intent) → provenance/sensitivity labels → PDP decision → PEP enforcement → proof/receipt recording.

**Why:** Any feature touching consequential actions in `L:\PROJECTS\arcana` must route through this pipeline; assuming capability alone authorizes action violates the design.

**How to apply:** Ensure requests carry proper intent binding relevant to the active task, and that executions produce recorded proofs.
