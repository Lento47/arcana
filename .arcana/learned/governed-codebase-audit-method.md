# governed codebase audit method

Audit order: sensitive-file inventory → built-in harnesses → dangerous-pattern sweeps → triage each hit

Sequence that worked for auditing Arcana:
1. Inventory untracked/sensitive files (`.pem`, `.vault/`) and confirm git-ignore coverage.
2. Run the project's own security harnesses (`authority-scan`, `authority-dynamic`, `assurance`, `conformance`) plus the full test suite before manual review — cheap coverage of governance-critical paths.
3. Sweep dangerous patterns: `new Function(`/`eval`, weak hashes (SHA-1/MD5), hardcoded-secret regexes.
4. Triage every hit: separate real issues from doc placeholders and test fixtures; for dynamic-eval sites, trace whether they actually bypass the PDP/PEP path.
5. Cross-check doc-comment claims about trust boundaries against actual control flow — evalCondition's comment claimed parity with tool-call gating and was wrong.

**Why:** Harnesses give fast broad coverage; targeted sweeps catch what they miss; verifying claims prevents trusting comments over code.

**How to apply:** Reuse this ordering for future audits of this or similar repos; stream interim progress to the user between long-running scans.
