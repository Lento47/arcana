# arcana evalcondition bypass

OPEN FINDING: workflow/engine.ts evalCondition runs model-authored JS via new Function, bypassing PDP/PEP

`evalCondition` in `workflow/engine.ts` evaluates model-authored JS expressions using `new Function` inside the trusted runtime process. Its doc comment claims the same trust boundary as model tool calls — this is false: tool calls pass through PDP/PEP with capabilities and approvals, while this eval bypasses governance entirely. A prompt-injected model could ship a condition expression that reads files, hits the network, or spawns processes — all unauthorized under the core invariant.

**Why:** This is the primary open vulnerability from the security audit; fix is pending.

**How to apply:** Candidate fixes: (1) replace raw eval with a sandboxed expression evaluator exposing no host references, (2) route condition evaluation through the PDP as a declared authority source so it appears in the scanner baseline, (3) at minimum restrict to a statically analyzed allowlist of safe expression forms. Verify chosen fix against `script/authority-scan.ts`.
