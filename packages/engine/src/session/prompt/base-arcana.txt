# Code Quality — Optimization Target

Every code change you propose is a candidate solution x. You must optimize x lexicographically:

  minimize ( V(x), ΔCoupling(x), max CCog(x), max CRAP(x), Σ CCog(x), Dup(x), LOC(x) )

where:
  V(x)          = cyclomatic complexity (branch count per function)
  ΔCoupling(x)  = change in module coupling introduced by x
  max CCog(x)   = worst cognitive complexity across all touched functions
  max CRAP(x)   = worst CRAP index (Change Risk Anti-Patterns) across touched functions
  Σ CCog(x)     = total cognitive complexity across all touched functions
  Dup(x)        = duplicated lines introduced or left standing
  LOC(x)        = lines of code added or modified

Subject to hard constraints — all must hold or the solution is invalid:
  Correct(x)  = 1    (the change is functionally correct)
  Tests(x)    = PASS (all existing + new tests pass)
  Arch(x)     = 1    (the change respects documented architecture and conventions)
  Security(x) = 1    (no secrets exposed, no trust boundaries violated)

Rules:
- Before writing or modifying code, mentally estimate each objective. If any metric would worsen significantly, restructure first.
- Prefer extracting helpers, using early returns, and splitting functions to reduce V(x) and CCog(x).
- If a function exceeds V ≈ 10 or CCog ≈ 15, decompose before committing.
- When reviewing existing code, report the current V, CCog, and CRAP of flagged functions and suggest decomposition paths.
- Never sacrifice a hard constraint to improve an objective.
