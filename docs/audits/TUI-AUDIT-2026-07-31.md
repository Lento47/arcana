# Arcana TUI Audit Report

- **Date:** 2026-07-31
- **Author:** Buffy (TUI CLIs + AI)
- **Scope:** `packages/tui` — Command Spine, chat cards, receipts, statusbar, which-key, dialogs, prompt, theme, background compositing
- **Method:** static code review of `packages/tui/src` against the OpenTUI reference docs in `.hermes/docs/opentui/` (wrap semantics, truncate prop, scrollbox). No runtime execution was performed.
- **Verification:** targeted `code_search` + full reads of spine, theme, chrome, and app surfaces. Findings are code-supported; runtime/terminal-behavior items are flagged as such.

---

## Executive summary

The Command Spine is visually ambitious and the layout contract (centralized width computation in `command-spine-shell.tsx`, dual-mode markdown, receipt grammar) is a real improvement over a raw transcript. But the surface is held together by **three conflicting minimum-width floors** (24, 40, 80), **five divergent truncation helpers** that all count UTF‑16 code units instead of display columns, **two duration formatters** (one mathematically wrong), and a spine that **casts its fully-typed theme to `Record<string, unknown>` and accesses every color through `as any`** — removing the compiler's ability to catch a single missing theme key.

Severity distribution of the 63 findings:

| Severity | Count | Categories hit |
| --- | --- | --- |
| High | 15 | overflow, off-screen, malformat, spine malpractice |
| Medium | 29 | truncation, malformat, color placement, bad design |
| Low | 19 | polish, dead code, consistency |

The single most impactful fix: make **one** display-width-aware truncation primitive and **one** width policy (`min(floor, term − chrome)` clamped to ≥1, never a bare 80 fallback), then delete the 80-column fallback in `spine-prose.tsx` that pushes markdown off screen on any narrow terminal. **(Both halves implemented — width policy §10.1, truncation primitive §10.4.)**

**Revision (same date):** every finding and fix below has been re-checked against the OpenTUI reference library (`.hermes/docs/opentui/` — layout, renderer, colors, scrollbox, markdown, text, code, env-vars) and the SolidJS library (`.hermes/docs/solidjs/` — signals, memos, fine-grained reactivity, list/conditional rendering). Where the framework ships a native API that replaces a hand-rolled workaround, the fix now names that API (§8). Where a Solid pattern violates fine-grained reactivity, it is called out (§9). AI SDK is not required: the spine consumes the already-normalized `@arcana/sdk/v2` `Part` union, so no AI SDK-level fix applies (see §8.0).

**Revision 2 (same date, implementation):** six of the top-confidence §8.3 fixes are now implemented, typecheck-clean, and verified with standalone assertion runners — the **width policy** (S5, B1-B4, O1: 80-fallback, 40-floor and shell 24-floor deleted; one `spineProseWidth` contract), the **background capability gate** (C1, D6: half-block compositing replaced by truecolor-gated OSC-11 dominant color), the **streaming markdown + fence-aware HR stripper** (M2, M8), the **display-width-aware truncation primitive** (T1-T5, O6: `Bun.stringWidth` + `Intl.Segmenter`; four duplicate truncators deleted), the **typed spine theme** (S1: `Record<string, unknown>` + `as any` color access removed across all spine files — which immediately surfaced the latent `report`-tone bug), and the **consolidated duration formatter** (T6/M6/M7: day-math fix, one canonical `Locale.duration` that `formatDuration` delegates to, unit-preserving `compactSpineElapsed`). Affected finding rows carry **→ FIXED (§10.x)** markers; full evidence in §10.

## 2. Truncation

The systemic issue: **every truncation helper in the TUI counts UTF‑16 code units** (`str.length`), while the terminal measures display columns. CJK/emoji glyphs render at 2 columns but count as 1, and multi-code-unit emoji can be split mid-glyph. The prompt already solved this in `prompt/display.ts` (`Intl.Segmenter` + `Bun.stringWidth`) — the rest of the TUI never adopted it.

## Cross-cutting root causes

1. **No display-width-aware truncation primitive.** `prompt/display.ts` proves the technique (`Intl.Segmenter` + `Bun.stringWidth`); everything else counts code units. Fix once in `locale.ts` (`truncate`, `truncateLeft`, `truncateMiddle`), then delete the 4 local duplicates (spine-mapper, spine-receipt, spine-header, spine-node). **RESOLVED (§10.4):** the shared helpers are now grapheme+width-aware, all four duplicates deleted, and every `Locale.truncate*` caller inherits the fix.
2. **Three conflicting width floors.** 24 (shell) / 40 (`spineProseWidth`) / 80 (`wrapCols` fallback). One policy: `width = max(1, min(floor, term − chrome))`, and `SpineProse` should take a *mandatory* numeric width with no 80 fallback. **RESOLVED (§10.1):** all three floors deleted; `spineProseWidth` (`max(1, term − chrome)`) is the one contract and `wrapCols` clamps ≥1.
3. **Type-erased theme access.** `Record<string, unknown>` + `as any` across every spine file. Replace with `Theme`-typed access; the compiler then catches the missing-token class of bug that currently renders as invisible color loss. **RESOLVED (§10.5):** `statusToneColor`/`spineTone` take `Theme` and return `RGBA`; all spine files (plus the gate routes and `ShimmerText`) read colors through the typed theme — and the latent `report`-tone bug (`theme.spineReport` was never a real token, silently `undefined`) was caught by the typing and fixed.
4. **Dual implementations of everything.** Two duration formatters (one buggy), two width contracts, two dialog providers, two shells, five truncators. Consolidation is the highest-leverage cleanup. **PARTIALLY RESOLVED:** width contracts consolidated (§10.1), truncators consolidated (§10.4), duration formatters consolidated (§10.6); dialog providers (D2) and shells (D3) still open.

## 9. Design, aesthetic, and performance best practices (grounded)

### 9.1 Design

1. **One width contract wins.** `spineProseWidth()` is exported and tested; the shell's private `proseWidth`/`codeWidth`/`thinkWidth` (24-floor) and `wrapCols` (80-fallback) must be deleted in its favor. The three-floor zoo (24/40/80) is the root of every off-screen finding (B1-B4, O1). **(DONE — §10.1.)**
2. **Standardize a scrollable dialog body primitive.** Inherited finding: `ArcanaSurface`, `DialogHelp`, and `ArtifactViewer` render unbounded content with no scroll owner. OpenTUI ships `ScrollBox` with `viewportCulling` + `stickyScroll` — one bounded body primitive for proof/help/artifact surfaces removes the whole clipping class (O3).

1. **Restore type safety on theme access.** `const t = themeObj as Record<string, unknown>` + `t.x as any` appears in every spine file. ### 9.3 Performance

1. **Kill render-thread timers.** The 250 ms scroll-button poll (D10) and the unconditional 200 ms pulse (S9) both re-render at fixed cadence. OpenTUI's `streaming` mode is incremental and finalizes on `streaming=false` — a single component, no thrash (M8, prose remount). **(DONE — §10.3.)**
3. **Memo purity.** The spine-mapper cache write inside `entries` memo (S6) risks re-triggering; keep memos pure per Solid guidance. The per-message parser LRU (8 MB byte-aware) and FNV strided hash are already good — keep. **✅ DONE — §10.19** (S6(a) memo-purity half; the monolith refactor itself stays open).
4. **`viewportCulling` + `stickyScroll` are on.** Confirmed on the spine scrollbox (`command-spine-shell.tsx`) — keep; they are the correct OpenTUI primitives for long transcripts (`scrollbox.mdx`).
5. **Clamp before layout, not after.** Negative widths (B5) and fractional paddings (B7) waste a layout pass; `Math.max(1, …)` + `Math.floor` at computation time.
6. **Gate decorative rendering on capabilities.** Background compositing and logo pulses (C1, D6) should check `renderer.capabilities` (truecolor) before enabling — otherwise they burn decode + composite work on every frame on terminals that cannot display them. **(DONE for background compositing — §10.2; the logo-pulse file is no longer present.)**
